# Tier 3 Mini-app Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mini-apps described by an `app.yaml` manifest can be installed and removed with `./dxos` without rebuilding the core. The plan ships the `tea-tour` and `hello` mini-apps.

**Architecture:**
- Each mini-app is its own container with its own Postgres schema and its own APISIX routes, generated by the `dxos` CLI from its manifest.
- The web app proxies `/apps/<id>/...` to the gateway and attaches the user's token on protected paths.
- Protected pages show inside the app shell in a sandboxed iframe without scripts.

**Tech Stack:**
- CLI: Python 3.12 with PyYAML, jsonschema and psycopg 3.
- Mini-apps: FastAPI with Jinja2 (`tea-tour`); `hello` uses only the standard library.
- Web: Next.js 14 route handlers and Prisma `$queryRaw`.
- Platform: APISIX 3.19 standalone YAML, Docker Compose.

**Spec:** `docs/specs/2026-11-11-tier3-miniapps-design.md`

## Review Focus

- **Two guests booking the last seats at the same moment:** never oversold, and the loser sees "Hết chỗ". Test in Task 8.
- **An app removed while a user still has its page open:** the next request answers 404 at once, with no cached app list. Test in Task 5.
- **An install that fails at the container step, for example a failing health check:** every earlier step is undone, `dxos list` does not show the app, and the gateway file equals what it was. Test in Task 4.
- **Booking a past or cancelled tour, or a tour through another HTX's URL:** refused with a Vietnamese message and nothing stored. Test in Task 8.
- **Running `make platform-up` again with apps installed:** the app routes stay in the gateway and the app containers keep running. Test in Task 4.

## Rulings (differences from the spec)

- **R1.** The web app reads `platform.installed_apps` with Prisma `$queryRaw`, not through Hasura (spec §9). The proxy must resolve apps for anonymous public requests, which carry no token. The table holds platform data that belongs to no HTX, so the Tier 2a rule "tenant reads go through the gateway" does not apply. No Hasura metadata is added.
- **R2.** The public rate limit sits in the web proxy, not in APISIX (spec §6.5). APISIX sees only the web container's IP on `:9081`. The proxy reuses the per-IP limiter that `/api/register` already has, moved into `apps/web/src/lib/ip-rate-limit.ts`.
- **R3.** The APISIX role check uses `openid-connect.claim_schema` on `realm_access.roles`, the same mechanism the existing `aud` check uses. The `tea-tour` manifest grants `/` to `manager` and `/guide` to `farmer` only (least privilege). The spec's example listed all three roles.
- **R4.** Spec §14 asked for the proxy risk to be checked in the first task. In this plan the gateway reload is proven in Task 2 and the proxy round trip in Task 5. Both come before the database and `tea-tour` work.

- Both kinds:
  - `upstream.nodes: {"app-<id>:<port>": 1}`
  - `proxy-rewrite.regex_uri: ["^/apps/<id>(/.*)?$", "$1"]` (an empty `$1` maps to `/`)

**Interfaces:**
- Produces:

Forwarding rules (spec §6.7):
- Reject any path segment `..`, `.` or empty, and any `%2e`, `%2f` or `%5c`, with 400.
- Public when the joined path starts with a manifest public prefix:
  - limited to 10/min per client IP (429)
  - no token attached
- Protected otherwise:
  - `getToken()`; when it fails, answer 401 with a short Vietnamese HTML page
  - attach `Authorization: Bearer <token>`
- The browser's `cookie`, `authorization` and `x-hasura-*` request headers are dropped.
- Method, body, `content-type`, `accept` and the query string are forwarded to `${CORE_GATEWAY_URL}/apps/<id>/<path>`, with `redirect: 'manual'` and `cache: 'no-store'`.
- From the response, keep status, body, `content-type` and `location`; drop `set-cookie`.
- Add the headers:
  - `Content-Security-Policy: default-src 'self'; script-src 'none'; style-src 'self'; img-src 'self' data:; form-action 'self'; frame-ancestors 'self'`
  - `X-Content-Type-Options: nosniff`
- An unknown or uninstalled app answers 404.
