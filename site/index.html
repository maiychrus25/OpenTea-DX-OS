Kiến trúc

Ba tầng, một lõi

Lõi dùng chung nằm ở dưới. Ứng dụng cho HTX nằm ở giữa. Mini-app cài thêm nằm ở trên, đi qua cổng API. Tầng dưới không phụ thuộc vào ứng dụng nào.

Yêu cầu tới mini-app: trình duyệt → web → cổng API → app.

Đọc dữ liệu lõi: app và web → cổng API → Hasura.

Tầng 1

Lõi dùng chung

  • Đăng nhập một lần và phân quyền theo HTX.
  • Nhật ký kiểm toán dạng chuỗi băm.

Tầng 2

Ứng dụng cho HTX

  • Web app: nhật ký, thửa, lô và QR.
  • Ứng dụng di động và máy tính cho nhân sự.

Tầng 3

Mini-app cài thêm

  • Khai báo bằng app.yaml, cài bằng ./dxos.
  • Bật theo từng HTX trong Kho ứng dụng.

Nhà phát triển

Thêm một mini-app mà không sửa lõi

Mini-app là một container riêng, cài bằng ./dxos. Lõi không được build lại.

bash
$ ./dxos install miniapps/tea-shop
# kiểm manifest; tạo schema và role nếu app khai báo database;
# sinh route cho gateway; chạy container. Lỗi ở bước nào thì các bước trước được hoàn tác.
# để app hiện trong menu, bật app cho HTX trong Kho ứng dụng (cần ./dxos worker).

Rút gọn từ miniapps/tea-shop/app.yaml (bỏ khối mô tả cửa hàng).

apiVersion: dxos/v1
id: tea-shop
name: Cửa hàng chè
description: Giới thiệu chè và nhận đơn đặt hàng.
version: 0.4.0
license: MIT
publisher: OpenTea Developers
requires: { core: ">=1.21.0" }
runtime:
  build: .
  port: 8080
  health: /healthz
routes:
  protected:
    /: [manager]
menu:
  - { label: Cửa hàng chè, path: /, roles: [manager] }

Manifest khai feed: app trả danh sách app con cho từng người dùng, ví dụ sổ do trưởng HTX tự tạo. Web gọi feed với token của người dùng và nhớ kết quả 15 giây.

{"entries": [{"label": "Sổ thu mua", "path": "/books/1", "icon": "leaf", "description": "Ghi chép thu mua"}],
 "create": {"label": "Tạo sổ", "path": "/new"}}

Sau make platform-up và make web-up. Lệnh ghi trong docs/miniapps.md và README.

make platform-up
make web-up
./dxos install miniapps/tea-shop
./dxos list
./dxos remove tea-shop
