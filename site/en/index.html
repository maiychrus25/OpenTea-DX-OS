Architecture

Three tiers, one core

The shared core sits at the bottom. Cooperative apps are in the middle. Installed mini-apps are at the top and reach the core through the API gateway. Nothing in the core depends on any app.

Requests to a mini-app: browser → web → API gateway → app.

Reading core data: apps and web → gateway → Hasura.

Tier 1

Shared core

  • Single sign-on and roles per cooperative.
  • Audit log as a hash chain.

Tier 2

Cooperative apps

  • Web app: journal, plots, lots and QR.
  • Mobile and desktop apps for staff.

Tier 3

Mini-apps

  • Declared in app.yaml, installed with ./dxos.
  • Turned on per cooperative in the App Store.

Developers

Add a mini-app without changing the core

A mini-app is its own container, installed with ./dxos. The core is not rebuilt.

bash
$ ./dxos install miniapps/tea-shop
# check the manifest; create the schema and role if the app declares a database;
# generate the gateway routes; start the container. If a step fails, the earlier steps are rolled back.
# to show the app in the menu, turn it on for the cooperative in the App Store (needs ./dxos worker).

Shortened from miniapps/tea-shop/app.yaml (store description block removed).

apiVersion: dxos/v1
id: tea-shop
name: Cửa hàng chè
description: Giới thiệu chè và nhận đơn đặt hàng.
version: 0.4.0
license: MIT
publisher: OpenTea Developers
requires: { core: ">=1.21.0" }
runtime:
  build: .
  port: 8080
  health: /healthz
routes:
  protected:
    /: [manager]
menu:
  - { label: Cửa hàng chè, path: /, roles: [manager] }

A manifest can declare a feed: the app returns a list of sub-apps for each user, for example a record book the manager creates. The web app calls the feed with the user's token and caches the result for 15 seconds.

{"entries": [{"label": "Sổ thu mua", "path": "/books/1", "icon": "leaf", "description": "Ghi chép thu mua"}],
 "create": {"label": "Tạo sổ", "path": "/new"}}

After make platform-up and make web-up. The commands are listed in docs/miniapps.md and the README.

make platform-up
make web-up
./dxos install miniapps/tea-shop
./dxos list
./dxos remove tea-shop

Locked-down container

No host port, read-only files, no internet access.

Data by cooperative

Every query is filtered by the cooperative code in the token.

Trust boundary

Each app has its own key, and the API gateway adds it to every request. Apps still share one network, so install only trusted apps.

Known limits

  • Tea leaf disease check: 0.87 on the same-source test set, 0.12 to 0.35 across sources; Thai Nguyen photos not measured.
  • The /storage/* route does not yet verify S3 SigV4 signatures.
  • Installed mini-apps share one internal network; from v1.24.0 each app accepts only requests through the gateway with its own key.
  • Mosquitto saves its state to disk every 60 seconds.
